# 后续验证计划

已确认 fnOS 内屏显示正常；Armbian 内屏尚未测试。以下列的是首次测试或补充验证工作，不否定 fnOS 已有显示结果。本次文档整理未连接设备或进行实机验收。

## 1. 每轮实验应保存的基线

- 实物型号、可确认的板卡/面板版本、供电与 USB 外设条件；公开前去除身份和网络凭据。
- 系统镜像名称与 SHA-256、`uname -a`、内核配置、启动参数、DTB 和模块哈希、对应源码提交及编译环境。
- 显示路径：HDMI 或 DSI、活动模式、模块绑定、fbcon/FbTerm；采用驱动内写入还是独立工具。
- 操作前后寄存器快照、服务日志、实屏照片/录像、开始与结束时间、失败和恢复情况。

## 2. 优先补齐的验收

| 项目 | 建议方法 | 应记录的结果 |
| --- | --- | --- |
| Armbian 内屏首次测试 | 针对 Armbian 内核构建、核对 DTB 和模块，再实测内屏 | 尚未测试，不预填正常显示结论 |
| fnOS 补充记录 | 在已确认显示正常的配置上保存源码、模块和配置指纹 | 可复现的版本、操作和实屏结果 |
| 启动可靠性 | 分别进行暖启动、断电冷启动及拔盘返回 Android | 次数、成功率、失败阶段和恢复方法；不预先宣称通过 |
| 几何与色彩 | 边框、非等距横竖带、黑白灰阶和 RGB 色块 | 裁剪、重复、通道次序、灰阶与可见偏色；如需宣称准确度需量化测量 |
| 显示持续性 | 记录明确时长的静态图、终端滚动和负载测试 | 抖动、黑屏、日志错误、温度及供电条件 |
| 生命周期 | 驱动重载、模式重设、HDMI 插拔及需要的休眠唤醒 | 配置是否被覆盖、是否能恢复；先保留回退路径 |
| 原因验证 | 在同一基线逐项修改/撤销寄存器配置 | 每项效果与组合效果；欠载推断需独立证据 |
| 横屏自启 | 核对内核旋转配置、sysfs 路径、服务是否跳过；单独检查 FbTerm | 登录与键盘是否可用、重启后方向、是否影响备用终端 |

## 3. 整机功能与恢复

触摸、Wi-Fi、GPU 加速、扬声器/麦克风、蓝牙、摄像头应各自完成功能测试，不能用模块加载或设备注册替代。fnOS 另需验证存储与实际 NAS 工作负载；USB 根文件系统需长时读写和异常断电恢复测试。

原厂分区备份与完整恢复流程分开验收。Linux DTB 禁用 eMMC 不约束 U-Boot 更新入口。先核对可用的离线启动文件和设备备份，再进行可能影响启动或显示的实验。

## 4. 已从源码发现、尚未修复的限制

- 独立 MMIO 工具没有板型/模式检查、写后回读、原值恢复；映射失败仍可能返回成功。
- 面板驱动直接访问 VPU/DSI 地址，未在映射失败时报告该项失败；需核验资源归属与 DRM 初始化先后顺序。
- systemd 的模块加载排序不能保证显示硬件就绪；一次写入也不保证之后不被覆盖。
- 当前没有统一的一键安装、DKMS、升级兼容或完整恢复方案。

这些项目来自静态阅读，文档整理不改变工具或驱动行为。

## 审计后优先补证

先确认 [证据索引](../evidence/README.md)列出的缺失材料和系统归属，再决定是否开展新实验。`0x1DF5` 的输出 FIFO 命名与头文件冲突，不应在未核对 S905L3A 定义时将其视为已确认欠载修复。源码问题集中见 [代码审计](code-audit.md)，本轮仅记录建议，不修改任何运行文件。

[实机记录](../evidence/fnos-live-check-2026-11-06.md)已补齐当前运行环境、DRM/DT状态、服务本次执行和磁盘文件哈希，并有用户实屏确认。下一步仍需精确源码/构建映射、区分驱动内与用户态修复贡献、冷启动和长期测试。现场旋转 unit 的 argv 问题已记录，未修复；当前横屏有内核启动参数支撑。Armbian 尚未测试。
