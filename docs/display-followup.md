# C10H 内置屏后续实测

## 横屏登录

U 盘 Armbian 的内核没有启用 `CONFIG_FRAMEBUFFER_CONSOLE_ROTATION`。当前由 systemd 在原生 DRM 启动后切到专用 `tty8`，运行 `fbterm -v -r 3 -s 20`，以 20 像素字号显示横向登录界面。FbTerm 内的登录提示退出后会重新打开，避免整个终端退出并切回 `tty1`。保留 `tty1` 作为备用控制台。

通过原厂 Android 再次暖启动 U 盘后，本次启动日志确认横屏服务自动启动，SSH 核验服务仍在运行、前台为 `tty8`。内核早期日志仍侧着显示，断电冷启动和本轮启动后的物理键盘操作尚未验收。

## 偏色与抖动

| 测试 | 结果 |
| --- | --- |
| XRGB8888 黑底，两半仅 X 字节不同 | 两半均偏蓝，抖动仍在 |
| 同模式、同几何图，切到独立 RGB565 缓冲 | 颜色与抖动无明显改善 |
| 关闭开机自动彩条，首次显示普通画面 | 已能看到抖动 |
| 同一次启动普通图 → 彩条 → 普通图 | 采样的 8 项寄存器恢复原值。固定六色图录像未复现切换前后变色 |
| 六色图，预期上排黑灰白、下排红绿蓝 | 色块位置正确。黑偏绿、白偏紫，下排依次偏亮绿、蓝紫、橙红 |
| 临时关闭 ENCL Gamma，读回 `0x31 → 0x30` | 六色图的主要偏色仍在。测试后已恢复 `0x31` |
| 原厂与 Linux 的 ENCL 硬件纯色 | 原厂红、绿、蓝顺序正确。Linux 对应测试值呈橙红、黄绿、蓝紫。原厂黑场未获照片确认 |

硬件纯色绕过普通 DRM 帧缓冲，因此偏色还需排查两条路径共用的 ENCL 输出、DSI 和面板。抖动在彩条切换前就已出现，单独追踪普通图像同步。六色图测试使用原生 `800×1280` 模式、一次原子图层提交和静态缓冲。

## 原厂对照

| 寄存器 | Android 正常画面 | Linux 普通画面 |
| --- | ---: | ---: |
| ENCL RGB 输出控制 `0x1CC1` | `0x402` | `0x402` |
| ENCL RGB 输入控制 `0x1CC7` | `0x3` | `0x3` |
| ENCL 滤波控制 `0x1CC2` | `0x0` | `0x0` |
| VPP 输出 FIFO 配置 `0x1D27` | `0xFFF01000` | `0xFFF01000` |
| VPP 行缓冲 `0x1D22` | `0x08080808` | `0x404` |
| VPP 矩阵控制 `0x1D5F` | `0x0` | `0x7800` |
| VPP 后级矩阵使能 `0x32BD` | `0x0` | `0x0` |
| OSD1 矩阵使能 `0x3D6D` | `0x0` | `0x0` |
| OSD1 HDR 控制 `0x38A0` | `0x1C040` | `0xC040` |

Android 内重新亮屏时，GPIO 动作与延时和 Linux 面板驱动配置一致。最后一段命令为 `11` → 约 120 ms → `29` → 约 30 ms → `35 00`。将 Linux 初始化表编码为 DSI 发送寄存器写入序列，152 项中有 151 项与原厂日志逐项匹配。剩余的 `3C 00 35` 数据未打印，包头可见，厂商参考驱动对 `0x3C` 走直接写入路径。日志记录的是主控写入，无法验证线上传输和面板实际接收。原厂 DCS `0x0B`、`0x0C` 多次读取不一致，暂不作为基线。

下一步补齐 DSI 主控和 PHY 的双边运行值，优先检查两种画面共用的输出配置。VPP 行缓冲差异保留为独立的抖动候选，修改前需核实字段及适用的 SoC 分支。
